# 经营分析前端交接

## 当前范围

本分支沿用现有页面样式，增加经营概览、数据与趋势、风险预警三个展示页面：

- /analysis：未来七天预订率、已预订均价、剩余房晚、近三十天取消率及规则预警。
- /analysis/trends：七天趋势、历史房型与渠道对比。
- /analysis/alerts：规则预警、阈值与计算依据。

这是一套可运行的前端演示，不是已接通后端的完整业务系统。AI、真实数据上传和 HTTP 接口均未接入，其他既有演示页面不在本次实现范围。

## 模拟数据与口径

src/data 下四个 JSON 来自项目配套 Python ToolGateway 分析工具的模拟数据结果。虚构民宿 DEMO001，数据快照截至 2026-09-21；不要解释为当天实时经营数据。

- overview.json：完整概览响应。
- overview-partial.json：缺少 2026-09-24 库存的概览响应。
- room_type.json、channel.json：2026-09-14 至 2026-09-20 历史对比结果。

页面可切换完整样例、缺少一天库存、尚未导入三种状态。缺失库存导致不可计算的数值保持 null，图表断开，不填零。渠道没有专属库存，因此不展示渠道入住率。预警为规则筛查，不代表因果分析或 AI 建议。

## 后端同学接入位置

共享展示组件：src/components/dashboard/analysis-dashboard.tsx。
格式化与图表转换：src/lib/analysis-format.ts。
目前组件直接导入 JSON；后续在数据获取层调用双方确认的接口，再把响应交给组件。当前没有实现或承诺任何可调用的服务地址。

接入时需约定并验证：

1. 民宿标识、查询区间与 as_of，以及响应中 data.metrics、data.trends、data.alerts 的嵌套结构。
2. 比例字段为 0–1 小数；金额为人民币元；房晚为整数；缺失值为 null。
3. 完整、部分缺失、空数据、加载中及接口失败的区分。目前只演示前三种。
4. 真实 CSV 校验、权限、数据持久化在后端实现；密钥不能放在前端。
5. 房型和渠道查询区间应与页面日期文案同步，移除当前固定日期与演示切换器。
6. AI 顾问由后续服务接入；成功连接后再更新“未连接”标识。

Python 工具与完整接口草案属于另行交付的工具包，本前端仓库没有包含 Python 后端。先参考上述 JSON 对齐字段，再由后端同学确定语言、框架和服务地址。

## 本地运行与检查

使用 Node.js 24，安装依赖后运行：

- npm run dev -- --host 127.0.0.1 --port 5173
- node --test tests/analysis.test.mjs
- npx tsc --noEmit
- npm run build

本地预览地址仅在运行开发服务的电脑上可用。GitHub 保存源码；线上 Lovable 页面是否更新取决于分支合并、同步与发布状态。
